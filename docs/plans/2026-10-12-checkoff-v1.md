# Checkoff v1

## Why

2026-10-12. Hardy wanted a Microsoft To Do style checklist without going back
to a Microsoft account: add tasks, check them off, and group a few steps under
one parent, for example a Jira ticket with three things to do. Mac native and
open source preferred.

Nothing open source is both native and able to nest tasks. Super Productivity
was the closest and he tried it the same day. It was too heavy for a checklist.
So this is a small app of our own.

Changed during the day: an optional due date was added. It must be optional
and sit at the side of the row.

## What v1 is

- One window, one list. Add, check off, rename, delete.
- Sub-tasks one level deep, by drag or by the `+` on a row.
- Reorder by drag. A right-click menu does the same moves without dragging.
- Optional due date at the right edge of the row, red when overdue.
- Done tasks stay in place, struck through, with a toggle to hide them.
- Left out on purpose: sync, reminders, notifications, Jira import, timers,
  multiple lists, and any count of open tasks.

## Decisions

- **Storage is one Markdown file** (`~/Checkoff/tasks.md`), not a database, so
  a person or a coding agent can read and edit it without the app. The app
  watches the file and re-reads it on change.
- **Every change re-reads the file first** and is applied to what is there now,
  so an edit made outside the app a moment earlier is not overwritten.
- **Checking a parent leaves its sub-tasks alone** and asks first if any are
  open.
- **Pure SwiftPM**, laid out like claude-usage-watcher-mac: a `CheckoffCore`
  library that holds all the logic and all the tests, and a thin SwiftUI app.
- **Distribution:** public Box-of-Raccoons repo, MIT, tag-driven release
  workflow that signs and notarizes. The repo stays local until v1 is tried
  and Hardy says to publish.

## Open

- Publish: create the public repo, push, tag `v0.1.0`.
- Drag and drop is tested as logic (where a drop lands, which moves are
  allowed) but has not been tried by hand with a real pointer.
